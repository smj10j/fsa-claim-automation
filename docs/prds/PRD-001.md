# PRD-001: Amazon Order Scanner

**Status**: `draft`
**Priority**: P0
**Effort**: L (1–2 weeks)
**Dependencies**: None
**Last updated**: 2026-03-18

---

## Problem

Users have hundreds of Amazon orders per year. Manually reviewing each one to find FSA-eligible purchases is tedious, error-prone, and often skipped entirely — leaving reimbursable money on the table. The extension must automatically surface eligible orders within the active FSA benefit year without any manual searching.

---

## Goals

1. Parse Amazon order history pages to extract all orders within the user's FSA benefit year date range.
2. Identify which orders and line items are likely FSA-eligible using keyword matching.
3. Surface results in the popup UI for user review, without requiring manual navigation.

## Non-Goals

- AI/ML-powered eligibility scoring (see PRD-004)
- Support for retailers other than Amazon (see PRD-008)
- Parsing orders from Amazon Business accounts (deferred)

---

## User Stories

| # | As a… | I want to… | So that… |
|---|-------|-----------|---------|
| 1 | User | Click "Scan Orders" in the popup | The extension automatically reviews my Amazon order history |
| 2 | User | See a list of potentially eligible orders with item names, dates, and amounts | I can quickly identify what to claim |
| 3 | User | Have the scanner handle pagination automatically | I don't have to manually load more orders |
| 4 | User | See only orders within my current FSA benefit year | I don't waste time on ineligible dates |
| 5 | User | Have scan progress reported back to the popup | I know the extension is working and not frozen |

## Functional Requirements

### FR-1: Trigger & Lifecycle
- Popup sends `SCAN_ORDERS_REQUEST` to service worker.
- Service worker opens (or reuses) an Amazon order history tab.
- Content script injected into `amazon.com/your-orders` performs scraping.
- Results streamed back via `SCAN_ORDERS_PROGRESS` messages, completed with `SCAN_ORDERS_COMPLETE`.

### FR-2: Date Filtering
- Use `benefit-year.ts` to compute `[startDate, endDate]` for the current FSA year.
- Skip orders with `orderDate` outside this range.
- Support both calendar-year FSAs (Jan–Dec) and plan-year FSAs (e.g., Jul–Jun).

### FR-3: Order Parsing
- Parse each order card on `/your-orders` to extract:
  - `orderId` (e.g. `113-1234567-8901234`)
  - `orderDate` (ISO string)
  - `orderTotal` (number, USD)
  - `items[]`: `{ name, quantity, price }`
  - `orderDetailUrl`
- Handle both "digital" and "physical" order card layouts.
- Handle gift card orders and Subscribe & Save orders (mark as special types).

### FR-4: Eligibility Pre-Filter
- Run each item name through `eligibility.ts` keyword matcher.
- Tag items with `eligibilityConfidence: 'likely' | 'possible' | 'unlikely'`.
- Surface orders that contain at least one `likely` or `possible` item.
- Store all orders (even ineligible) in `chrome.storage.local` so the user can manually review.

### FR-5: Pagination
- Detect "Next page" button on order history.
- Automatically click through pages until all orders in the benefit year are scanned, or until a configurable page limit (default: 20 pages) is reached.
- Stop early if page dates fall entirely before `startDate`.

### FR-6: Progress Reporting
- After each page is parsed, emit `SCAN_ORDERS_PROGRESS` with `{ scanned, total, eligible }` counts.
- Popup displays a live progress bar and counts.

### FR-7: Error Handling
- If Amazon redirects to login, emit `SCAN_ORDERS_ERROR` with `code: 'NOT_AUTHENTICATED'`.
- If selectors fail to match (DOM change), emit with `code: 'SELECTOR_ERROR'` and a diagnostic payload.
- Retry individual pages up to 2 times on transient errors.

## Technical Notes

- All DOM selectors live in `src/constants/selectors.ts` — never hardcode in scanner.
- Content script communicates back via `chrome.runtime.sendMessage` (not `postMessage`).
- Use `MutationObserver` to detect when order cards are rendered before scraping.
- Persist intermediate results to storage after each page in case of interruption.
- The scanner must be re-entrant: if a scan is already in progress, deduplicate.
