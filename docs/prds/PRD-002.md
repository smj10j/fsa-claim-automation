# PRD-002: Invoice Capture & Management

**Status**: `draft`
**Priority**: P0
**Effort**: M (3–5 days)
**Dependencies**: PRD-001
**Last updated**: 2026-03-18

---

## Problem

FSA claim portals require itemized receipts as proof of purchase. Amazon order confirmation emails are acceptable but hard to attach programmatically. Users currently screenshot or print-to-PDF individual order detail pages — a slow, manual process that creates friction and causes claims to be abandoned. The extension must automatically capture and store ready-to-upload receipts for each eligible order.

---

## Goals

1. Navigate to each eligible Amazon order detail page and capture a full-page screenshot.
2. Store the captured images persistently in `chrome.storage.local`.
3. Expose captured invoices in the popup UI so users can preview them before submitting.
4. Produce captures that are accepted by FSA portals (legible, correctly formatted).

## Non-Goals

- PDF generation (screenshots are sufficient for MVP; see backlog)
- Capturing invoices from retailers other than Amazon (see PRD-008)
- Sending invoices via email or cloud storage

## Functional Requirements

### FR-1: Capture Trigger
- After `SCAN_ORDERS_COMPLETE`, popup shows a "Capture Invoices" step.
- Service worker queues `CAPTURE_INVOICE_REQUEST` for each order marked for claiming.
- Captures are processed sequentially (not parallel) to avoid tab spam.

### FR-2: Navigation
- Service worker opens each Amazon order detail URL in a background tab.
- Content script waits for the order detail DOM to fully load (`DOMContentLoaded` + idle check).
- Tab is closed after capture completes or fails.

### FR-3: Screenshot Capture
- Use `html2canvas` to render the full order detail page content to a canvas.
- Crop to the relevant order summary section (not the full page with nav/footer).
- Output: base64-encoded PNG, max ~500KB per image (compress if needed).

### FR-4: Storage
- Store each invoice as `invoice:{orderId}` → `{ dataUrl, capturedAt, width, height }` in `chrome.storage.local`.
- Storage quota check: warn user if available storage < 5MB before starting capture batch.
- Images older than 90 days (configurable) are eligible for cleanup (not automatic deletion).

### FR-5: Popup Preview
- In the invoice review step, each order card shows:
  - Thumbnail of the captured invoice
  - "Preview full size" button (opens in new tab)
  - "Re-capture" button
  - "Remove" button (with confirmation)

### FR-6: Error Handling
- If `html2canvas` fails (e.g. CORS, missing DOM), mark invoice as `status: 'capture_failed'`.
- Show user a fallback option: "Upload manually" (stores a user-provided file blob instead).
- Retry capture once before marking as failed.

### FR-7: Format Validation
- After capture, run basic validation: non-zero dimensions, non-blank image (pixel variance check).
- Flag suspiciously small or blank captures for user review.

## Technical Notes

- `html2canvas` must be bundled in the content script, not loaded from CDN (CSP restrictions).
- Amazon order detail pages load asynchronously — use `MutationObserver` + idle detection.
- `chrome.storage.local` quota is 10MB by default; with `unlimitedStorage` permission it is unlimited — request this permission.
- Store invoices separate from `AppState` under `invoice:*` keys for easy cleanup.
- Consider using `OffscreenDocument` for rendering if content script capture proves unreliable.
