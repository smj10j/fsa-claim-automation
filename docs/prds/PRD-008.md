# PRD-008: Multi-Retailer Support

**Status**: `draft`
**Priority**: P2
**Effort**: XL (2–4 weeks)
**Dependencies**: PRD-001, PRD-002
**Last updated**: 2026-03-18

---

## Problem

Amazon is the most convenient place to buy FSA-eligible products online, but users also shop at Walgreens, CVS, Target, Costco, and FSA Store — especially for health and medical items. Every non-Amazon FSA purchase the extension misses is potential reimbursement left behind. Supporting more retailers also insulates the extension against Amazon DOM changes breaking the core scan.

---

## Goals

1. Support order history scanning and invoice capture for the top 5 non-Amazon retailers.
2. Create a retailer abstraction layer (mirroring PRD-007's provider pattern) for extensibility.
3. Produce invoice captures in a consistent format regardless of retailer.

## Non-Goals

- Point-of-sale / physical store receipt capture (out of scope — digital only)
- Parsing emailed receipts (interesting future feature but different architecture)
- Supporting every online retailer (long tail; community-driven)

## Functional Requirements

### FR-1: Retailer Abstraction Interface
```typescript
interface RetailerAdapter {
  id: string                    // e.g., 'walgreens', 'cvs', 'target'
  name: string
  orderHistoryDomain: string    // e.g., 'walgreens.com'
  orderHistoryUrl: string       // Direct URL to order history

  // Scraping
  scrapeOrderList(doc: Document): ScrapedOrder[]
  scrapeOrderDetail(doc: Document, url: string): OrderDetail
  getOrderDetailUrl(orderId: string): string

  // Invoice
  captureInvoiceSection(doc: Document): HTMLElement
}
```

### FR-2: Supported Retailers (v1)

| # | Retailer | Why | Notes |
|---|----------|-----|-------|
| 1 | Amazon | MVP — already targeted | PRD-001 |
| 2 | Walgreens | Major pharmacy, heavy FSA inventory | walgreens.com |
| 3 | CVS | Major pharmacy, "CVS Health" brand alignment | cvs.com |
| 4 | FSA Store | 100% FSA-eligible inventory — high signal | fsastore.com |
| 5 | Target | Large pharmacy + OTC section | target.com |
| 6 | Costco | Popular for bulk health items | costco.com |

### FR-3: Multi-Source Scan Flow
- Popup scan step updated: "Scan All Sources" or individual retailer toggles.
- Service worker orchestrates scans across all configured retailers sequentially.
- Results merged into a unified `AmazonOrder[]` (rename to `RetailerOrder[]`) list with `retailerId` field.
- Progress shows per-retailer status: "Amazon ✓ | Walgreens ✓ | CVS (scanning...)"

### FR-4: Retailer-Specific Eligibility Boost
- FSA Store items → automatically `eligibilityConfidence: 'high'` (100% FSA-eligible store).
- Walgreens/CVS items in "Health & Medicine" category → `eligibilityConfidence: 'high'` (pharmacy-curated FSA sections).
- Amazon items use standard scoring (PRD-004).

### FR-5: Invoice Capture Consistency
- Each retailer adapter implements `captureInvoiceSection` returning the relevant DOM element.
- Core capture logic (`invoice-capture.ts`) applies `html2canvas` to that element.
- Output format is identical regardless of retailer.
- Invoice metadata includes `retailerName` so claim form can populate "Merchant" correctly.

### FR-6: Authentication Detection
- If a retailer's order history page requires login, emit `RETAILER_AUTH_REQUIRED` with the retailer's login URL.
- Popup shows: "Please log in to Walgreens to scan your orders" with a "Go to Walgreens" button.

### FR-7: Retailer Configuration in Settings
- Settings page (PRD-010) lists all supported retailers with on/off toggles.
- Retailers with no order history default to off (not scanned unless opted in).
- "Add retailer account" prompts user to visit the retailer and confirms auth.

## Technical Notes

- Rename `AmazonOrder` → `RetailerOrder` with `retailerId: string` field (breaking change, needs migration).
- `src/constants/selectors.ts` → `src/constants/selectors/amazon.ts`; each retailer gets its own file.
- FSA Store: since 100% of products are FSA-eligible, scraping is simpler (no eligibility filtering needed).
- Walgreens and CVS have well-structured order history pages — likely simpler to scrape than Amazon.
- Target uses React for its storefront — may need React-aware DOM waiting similar to Navia.
