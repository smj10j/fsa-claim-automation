# PRD-004: Smart Eligibility Engine v2

**Status**: `draft`
**Priority**: P1
**Effort**: M (3–5 days)
**Dependencies**: PRD-001
**Last updated**: 2026-03-18

---

## Problem

The MVP eligibility engine uses simple keyword matching against product names. This produces two failure modes that erode user trust and value:

1. **False negatives**: Eligible items get missed because their names don't contain obvious FSA keywords (e.g., "Hydrocolloid Pimple Patch" is FSA-eligible but may not match basic keyword lists).
2. **False positives**: Non-eligible items get flagged (e.g., "Vitamin C supplement" — vitamins are generally not FSA-eligible, but exceptions exist).

A smarter engine increases the amount of money users recover and reduces the frustrating experience of having claims denied.

---

## Goals

1. Increase eligible item detection rate with richer signal sources (Amazon category, ASIN metadata, product description).
2. Reduce false positives with category-level exclusion rules and confidence scoring.
3. Give users a transparent, editable eligibility determination they trust.
4. Build a feedback loop so user corrections improve future scans.

## Non-Goals

- LLM/AI API calls (no external network calls for privacy; all logic runs locally)
- Guaranteed eligibility determination (legal disclaimer always required)
- Integration with IRS publication 502 automated parsing

## Functional Requirements

### FR-1: Multi-Signal Scoring
Compute `eligibilityScore: number (0–1)` and `eligibilityConfidence: 'high' | 'medium' | 'low' | 'unlikely'` for each item using a weighted combination of:

| Signal | Weight | Source |
|--------|--------|--------|
| Product name keyword match | 0.4 | `item.name` vs `eligibility-list.ts` |
| Amazon product category match | 0.3 | Category string scraped from order detail |
| Negative keyword exclusion | −0.5 | e.g., "gummy", "vitamin", "supplement" unless RX |
| User override (explicit yes/no) | 1.0 | Overrides all other signals |
| ASIN allowlist match | 0.9 | Curated ASIN database (see FR-4) |

### FR-2: Confidence Thresholds

| Confidence | Score Range | Action |
|------------|-------------|--------|
| `high` | 0.75–1.0 | Auto-select for claiming; green badge |
| `medium` | 0.4–0.74 | Shown with yellow badge; user review recommended |
| `low` | 0.1–0.39 | Shown collapsed; "might be eligible" |
| `unlikely` | 0–0.09 | Hidden by default; "show ineligible items" toggle |

### FR-3: Reasoning Transparency
- Each item's `EligibilityResult` includes a `reasons: string[]` array explaining the determination.
- Example: `["Name matches 'bandage' (wound care)", "Amazon category: Health & Household > First Aid"]`
- Displayed as a tooltip or expandable row in the popup.

### FR-4: Curated ASIN Allowlist/Denylist
- Maintain `src/constants/asin-database.ts` with known eligible/ineligible ASINs.
- Seed with top ~500 FSA Store top-sellers and common false positives.
- ASINs are extracted from Amazon order detail URLs during order scanning.
- Format: `{ asin: string, eligible: boolean, category: string, note?: string }[]`

### FR-5: User Override & Persistence
- User can click "Mark Eligible" / "Mark Ineligible" on any item in the popup.
- Override stored in `chrome.storage.local` under `eligibility-overrides` as `{ [itemName: string]: boolean }` (keyed by normalized item name).
- Overrides applied before scoring so they always win.
- Override UI shows "You marked this eligible on [date]" with an "Undo" option.

### FR-6: Category Extraction
- During order scan (PRD-001), if order detail page is available, scrape the Amazon product category breadcrumb (e.g., "Health & Household > Medical Supplies & Equipment > ...").
- Store as `item.amazonCategory` on `OrderItem`.
- Category matching rules in `src/constants/eligibility-list.ts` (category → eligibility mapping).

### FR-7: Exclusion Rules
- Maintain `src/constants/exclusion-list.ts` with category/keyword exclusion rules.
- Examples:
  - Vitamins & Supplements → ineligible (unless prescribed)
  - Cosmetics → ineligible (sunscreen exception: SPF 15+ is eligible)
  - Food & Grocery → ineligible
  - Baby → partially ineligible (thermometers yes, diapers no)
- Exclusion rules evaluated after keyword matching.

## Success Metrics

| Metric | Target |
|--------|--------|
| Eligible item detection rate (recall) | ≥ 90% (vs ~70% for keyword-only) |
| False positive rate (precision) | < 5% for `high` confidence items |
| User override rate | < 15% of items (lower = better accuracy) |
| Engine latency (1000 items) | < 500ms |

---

## Technical Notes

- All logic must be pure functions — no I/O, no network calls — for testability.
- `eligibility.ts` becomes a thin orchestrator calling sub-modules (keyword, category, asin, override).
- ASIN extraction from Amazon order detail URL: `amazon.com/dp/{ASIN}` or `amazon.com/gp/product/{ASIN}`.
- Scoring is deterministic for the same inputs — results are reproducible.

## Acceptance Criteria

- [ ] `eligibility.ts` accepts `OrderItem` with optional `amazonCategory` and `asin` and returns `EligibilityResult` with score, confidence, and reasons
- [ ] Multi-signal scoring weights are configurable constants
- [ ] ASIN allowlist/denylist seeded with ≥ 100 known entries
- [ ] User overrides persist across sessions and win over all other signals
- [ ] `eligibility-list.ts` and `exclusion-list.ts` are separate, well-documented files
- [ ] Unit tests achieve ≥ 90% coverage of scoring logic
- [ ] False positive test suite: vitamins, cosmetics, food items return `unlikely`
- [ ] False negative test suite: sunscreen (SPF 15+), hydrocolloid patches, FSA Store top sellers return ≥ `medium`
