# PRD-011: Invoice-First FSA Detection via Amazon's Native FSA Label

**Status**: `in-progress`
**Priority**: P0
**Effort**: M (2–3 days)
**Dependencies**: PRD-001 (Amazon Order Scanner), PRD-002 (Invoice Capture)
**Last updated**: 2026-03-18

---

## Problem

The current eligibility engine uses keyword matching on product titles. This has two fundamental issues:

1. **Wrong signal**: Keyword matching on a product title is a heuristic. Amazon itself already knows exactly which items are FSA/HSA eligible and shows this on every invoice page — including the exact dollar amount eligible. We're ignoring the authoritative source.

2. **Wrong amount**: When a claim is built today, we use `order.totalAmount` for the claim. But if an order had both eligible and non-eligible items, the total is wrong. Amazon's FSA label shows the *exact* eligible subtotal.

Amazon displays on the invoice/print page:
```
FSA or HSA eligible:  $34.97
```

This is the ground truth — it's the same number Navia would accept. We should use it.

---

## Proposed Solution

Restructure the scanning workflow to visit every order's invoice page during the scan phase, check for the FSA label, and capture the screenshot in the same page visit. This replaces the separate "Capture Invoices" step entirely.

### New Workflow

```
Old:  Scan Orders → Review → Select → Capture Invoices → Submit
New:  Scan Orders → Scan Invoices (auto) → Review → Select → Submit
```

**Step 1 — Scan Order History** (`scanning_amazon`):
- Collect ALL order IDs + dates within the benefit year.
- Remove keyword-match eligibility gating. Every order in the benefit year is a candidate.
- Orders arrive with `invoiceScanStatus: "pending"`.

**Step 2 — Scan Invoices** (`scanning_invoices`, new):
- Automatically navigate to each order's print invoice page, one at a time.
- Extract the "FSA or HSA eligible: $X.XX" amount if present.
- Capture a screenshot of the invoice in the same visit.
- Mark orders: `invoiceScanStatus: "confirmed"` (label found) or `"no_label"` (not found).
- Show progress in the popup: "Scanning invoices: 12 / 47".

**Step 3 — Review Orders** (`reviewing_orders`):
- Show only `confirmed` orders (Amazon confirmed FSA eligibility).
- Each order shows Amazon's exact FSA eligible amount (not the order total).
- Invoices are already captured — no separate capture step.

**Step 4 — Select & Submit** (unchanged):
- User selects orders to claim.
- Claim amount = `fsaEligibleAmount` (from Amazon label) rather than `totalAmount`.
- Go directly to Navia form filling.

---

## Goals

1. Use Amazon's own FSA label as the primary eligibility signal (more accurate than keywords).
2. Get the exact FSA-eligible dollar amount per order from Amazon (more accurate for claims).
3. Eliminate the separate "Capture Invoices" step (captured during invoice scanning).
4. Keep keyword matching as a displayed hint for orders Amazon doesn't label (transparency).

## Non-Goals

- Replacing keyword matching entirely (keep as secondary display/fallback signal).
- Supporting retailers other than Amazon.
- Handling orders where FSA eligibility is split across line items differently than Amazon computes.

| # | As a… | I want to… | So that… |
|---|-------|-----------|---------|
| 1 | User | Have every order in my benefit year checked automatically | I don't miss eligible items that keyword matching would miss |
| 2 | User | See Amazon's exact FSA-eligible amount on each order | My claim amounts are accurate and Navia won't reject them |

## Functional Requirements

### FR-1: Collect All Benefit-Year Orders
- `order-scanner.ts`: Remove the `eligibleItems.length === 0` guard. Emit ALL orders within the benefit year, regardless of keyword matching.
- Keep running `filterEligibleItems` on items (for display and keyword-match metadata), but do not use it to gate order inclusion.

### FR-2: Invoice Scan Step
- New `WorkflowStep`: `"scanning_invoices"`.
- After `SCAN_ORDERS_RESULT` with `hasNextPage: false`, service worker automatically transitions to `scanning_invoices` and begins navigating to invoice pages.
- Navigate to `https://www.amazon.com/gp/css/summary/print.html?orderID={orderId}` for each pending order.
- Content script (`invoice-capture.ts`) runs, extracts FSA amount + captures screenshot, sends `INVOICE_SCAN_RESULT`.

### FR-3: FSA Label Extraction
- In `invoice-capture.ts`: search the page for text matching `"FSA or HSA eligible"` (case-insensitive).
- Extract the dollar amount from the same element or adjacent sibling.
- Parse to cents.
- Add selector to `AMAZON_SELECTORS.orderDetail.fsaLabel`.

### FR-4: Combined Result Message
- New message: `INVOICE_SCAN_RESULT { orderId, fsaEligibleAmountCents: number | null, dataUrl: string | null }`.
- `fsaEligibleAmountCents: null` means label not found (order is not Amazon-confirmed FSA eligible).
- `dataUrl: null` means screenshot capture failed (distinct from label not found).

### FR-5: Order State Tracking
- Add to `AmazonOrder`:
  - `invoiceScanStatus: "pending" | "scanning" | "confirmed" | "no_label"` — tracks where we are in the invoice scan for this order.
  - `fsaEligibleAmount?: number` — cents, from Amazon's label. Present only when `invoiceScanStatus === "confirmed"`.
  - `eligibilitySource?: "amazon_label" | "keyword_match"` — for UI display.

### FR-6: Scan Progress
- Add `invoiceScanProgress: { total: number; scanned: number }` to `AppState`.
- Updated after each `INVOICE_SCAN_RESULT`.
- Popup displays: "Scanning invoices: {scanned} / {total}".

### FR-7: Claim Amount Uses Amazon Label
- In `buildClaimsFromOrders`: if `order.fsaEligibleAmount` is set, use it as the claim `amount`. Otherwise fall back to `totalAmount`.

### FR-8: Remove Capturing Invoices Step
- The `capturing_invoices` WorkflowStep and associated UI/messages are no longer part of the happy path.
- Remove the "Capture Invoices" button from the popup.
- Invoices are captured during `scanning_invoices`; by the time `reviewing_orders` is reached, all screenshots exist.
- Keep the step definition in the type for backward-compat with stored state, but the flow never enters it.

### FR-9: Popup Updates
- Show `scanning_invoices` as its own step in the progress indicator, with a count.
- On `reviewing_orders`, show `eligibilitySource` badge: "Amazon confirmed" (green) vs "keyword match" (yellow).
- Show `fsaEligibleAmount` (not `totalAmount`) on order cards when available.

## Technical Design

### New message types (messages.ts)
```ts
// Amazon CS → SW
| { type: "INVOICE_SCAN_RESULT"; orderId: string; fsaEligibleAmountCents: number | null; dataUrl: string | null }
| { type: "INVOICE_SCAN_ERROR"; orderId: string; message: string }
```

### New workflow step (state.ts)
```ts
WorkflowStep = ... | "scanning_invoices" | ...
// "capturing_invoices" kept for type compat but not used in new flow
```

### AmazonOrder additions (order.ts)
```ts
invoiceScanStatus?: "pending" | "confirmed" | "no_label";
fsaEligibleAmount?: number; // cents, from Amazon FSA label
eligibilitySource?: "amazon_label" | "keyword_match";
```

### Service worker state machine changes
```
SCAN_ORDERS_RESULT (hasNextPage=false)
  → currentStep: "scanning_invoices"
  → begin navigating to invoice pages

INVOICE_SCAN_RESULT (fsaEligibleAmountCents != null)
  → save invoice screenshot
  → update order: invoiceScanStatus="confirmed", fsaEligibleAmount=N
  → navigate to next pending order

INVOICE_SCAN_RESULT (fsaEligibleAmountCents == null)
  → update order: invoiceScanStatus="no_label"
  → navigate to next pending order

all orders scanned
  → currentStep: "reviewing_orders"
  → popup shows only "confirmed" orders
```

### Selector for FSA label
```ts
// In selectors.ts orderDetail section
fsaLabel: '[class*="fsa"], [id*="fsa"]',  // fallback: text search
fsaLabelText: "FSA or HSA eligible",       // text search string
```

Note: Amazon's DOM doesn't have stable class/ID for the FSA label — we'll use `TreeWalker` text search to find the element containing "FSA or HSA eligible" text and extract the adjacent price.

## Tradeoffs & Risks

| Risk | Mitigation |
|------|-----------|
| Many orders → slow invoice scan | Show progress; allow background scanning while popup is closed |
| Amazon doesn't label all FSA-eligible items | Keep keyword match as fallback signal shown in UI |
| Print invoice page layout changes | Robust text search (not selector-based) for FSA label |
| User has 200+ orders in benefit year | Add a fast pre-filter: skip orders where keyword scan returned no matches AND order total < $5 |
| Screenshot capture fails on some pages | Treat as `dataUrl: null`; still record FSA amount if label found |
