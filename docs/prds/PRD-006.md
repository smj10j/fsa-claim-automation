# PRD-006: Claim History & Status Monitor

**Status**: `draft`
**Priority**: P1
**Effort**: M (3–5 days)
**Dependencies**: PRD-003
**Last updated**: 2026-03-18

---

## Problem

After submitting claims, users have no way to know which ones were approved, denied, or are still pending without manually logging into the Navia portal and checking each one. This creates anxiety and means users often re-submit duplicate claims or miss denied claims that need to be corrected. The extension should be the authoritative record of all claims and should proactively surface status updates.

---

## Goals

1. Maintain a persistent archive of all claims ever submitted through the extension.
2. Automatically poll the Navia portal for status updates and notify the user of changes.
3. Surface actionable next steps for denied or pending claims.
4. Provide a lifetime view of FSA reimbursements recovered through the extension.

## Non-Goals

- Legal or tax advice on denied claims
- Automatic resubmission of denied claims
- Integration with Navia's official API (there isn't one)

---

## User Stories

| # | As a… | I want to… | So that… |
|---|-------|-----------|---------|
| 1 | User | See a list of all claims I've submitted with their current status | I have a single source of truth |
| 2 | User | Get notified when a claim is approved or denied | I don't have to keep checking the portal |
| 3 | User | See the reason a claim was denied | I know what to fix if I resubmit |
| 4 | User | See my total lifetime reimbursements through the extension | I understand the value I've gotten |
| 5 | User | Filter claims by status, date range, or amount | I can find specific claims quickly |
| 6 | User | See which claims are still pending and for how long | I can follow up if one is stuck |

## Functional Requirements

### FR-1: Claim Record Schema
Each stored `Claim` object extends with:
```typescript
{
  claimId: string          // Extension-generated UUID
  portalClaimId?: string   // ID assigned by Navia after submission
  status: 'draft' | 'submitted' | 'pending' | 'approved' | 'denied' | 'resubmitted'
  submittedAt?: string     // ISO timestamp
  resolvedAt?: string      // When approved/denied
  denialReason?: string    // Scraped from portal if denied
  approvedAmount?: number  // May differ from claimed amount
  lastCheckedAt?: string   // Last time status was polled
}
```

### FR-2: History UI in Popup
- New "History" tab in popup (alongside the main workflow).
- Claims list with:
  - Status badge (Approved ✓, Pending ⏳, Denied ✗, Draft)
  - Merchant, date, amount, and approved amount (if different)
  - Expandable row showing: items, invoice thumbnail, denial reason
- Filter bar: status filter chips, date range picker, search by amount
- Summary row at top: "Total approved: $1,247 | Pending: $89 | Denied: $34"

### FR-3: Navia Status Polling
- `chrome.alarms` triggers status check once per day (or on popup open).
- Service worker injects a status-checker content script on `navia.com/claims` (or equivalent).
- Script scrapes claim list: `portalClaimId`, `status`, `resolvedDate`, `approvedAmount`, `denialReason`.
- Matches portal records to local claims by date + amount + merchant (since portal IDs aren't known at submission time).
- Updates `Claim.status` and `Claim.lastCheckedAt` in storage.

### FR-4: Status Change Notifications
- When a claim status changes from `pending` → `approved` or `denied`:
  - Fire `chrome.notifications` alert: "Your $47 Amazon claim was approved!" or "Your $32 Amazon claim was denied: [reason]"
  - Notification links to History tab in popup.
- Batch notifications if multiple claims change at once: "3 claims approved totaling $142."

### FR-5: Denied Claim Guidance
- For denied claims, show contextual guidance based on denial reason:
  - "Documentation missing" → "Re-capture invoice and resubmit"
  - "Not FSA eligible" → "Remove from claims or consult your plan administrator"
  - "Outside benefit year" → "This expense is outside your plan year"
- "Resubmit" button on denied claims re-opens the PRD-003 flow for that claim with pre-filled data.

### FR-6: Lifetime Stats
- Dedicated stats card on History tab:
  - Total claimed (all time)
  - Total approved (all time)
  - Total pending
  - Total denied
  - Approval rate percentage
  - "Time saved" estimate: (number of claims × 3 minutes per manual claim)
- These numbers are a powerful retention and conversion hook.

### FR-7: Data Persistence & Retention
- Claims stored indefinitely in `chrome.storage.local` (no auto-deletion).
- When storage approaches limits, offer to export old claims to JSON before pruning.
- Claim invoices (base64 images) eligible for cleanup after 1 year or manual trigger.

## Technical Notes

- Matching portal records to local claims requires fuzzy matching (date ± 1 day, amount ± $0.01) since portal may round or use different timezone.
- Portal scraping must handle Navia's SPA navigation — use `form-observer.ts` patterns.
- Status polling should be passive (triggered when user navigates to navia.com) to avoid unexpected Navia tab opens.
- `chrome.storage.local` claim archive should be a flat array, not nested under `AppState`, to avoid hitting quota with large histories.
