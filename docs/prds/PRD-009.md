# PRD-009: Onboarding & Guided Setup Wizard

**Status**: `draft`
**Priority**: P1
**Effort**: S (1–2 days)
**Dependencies**: PRD-001, PRD-003
**Last updated**: 2026-03-18

---

## Problem

A new user who installs the extension faces several hurdles before getting value: granting permissions, setting up their FSA provider, understanding what the extension does, and knowing how to start. Without clear guidance, most new users bounce before completing their first scan. The onboarding experience is the single most important factor in activation rate — and activation is necessary for any paid conversion.

---

## Goals

1. Guide first-time users through setup in under 2 minutes.
2. Collect the minimum necessary configuration (FSA provider, benefit year dates).
3. Set correct expectations about what the extension does and what it can't do.
4. Get the user to their first successful scan as fast as possible.

## Non-Goals

- Account creation or cloud sync
- Video tutorials (too heavy for MVP)
- Automated provider detection without user confirmation

---

## User Stories

| # | As a… | I want to… | So that… |
|---|-------|-----------|---------|
| 1 | New user | See a clear welcome screen explaining what the extension does | I understand the value immediately |
| 2 | New user | Be guided through granting necessary permissions | I don't get stuck on a confusing permissions prompt |
| 3 | New user | Select my FSA provider in one click | The extension knows where to submit my claims |
| 4 | New user | Confirm my benefit year dates | The scan finds the right orders |
| 5 | Returning user | Skip onboarding if I've already set up | The extension doesn't annoy me with repeated setup |
| 6 | User | Re-run onboarding if I change providers | I can reconfigure without reinstalling |

## Functional Requirements

### FR-1: First-Run Detection
- On popup open, check `AppState.onboardingComplete: boolean`.
- If `false` (default), redirect to onboarding flow instead of main workflow.
- Onboarding is a separate React route: `/onboarding`.

### FR-2: Onboarding Steps

**Step 1: Welcome**
- Extension name, logo, one-line value prop: "Automatically find and submit your FSA claims from Amazon."
- List of 3 key benefits with icons:
  - "Scan Amazon orders for FSA-eligible items"
  - "Auto-fill your FSA portal with one click"
  - "Never miss a year-end deadline"
- CTA: "Get Started →"

**Step 2: Permissions**
- Explain why each permission is needed (user-friendly language):
  - `tabs`: "To open Amazon and your FSA portal"
  - `storage`: "To save your claims and invoices locally (never uploaded)"
  - `notifications`: "To remind you before your FSA deadline"
  - Host permissions for Amazon/Navia: "To scan orders and fill forms"
- Show permission status: granted ✓ / not yet
- "Grant Permissions" button triggers `chrome.permissions.request`
- If user denies optional permissions, explain impact and offer "Skip for now"

**Step 3: Choose FSA Provider**
- Grid of provider logos + names (from PRD-007 list)
- "Not listed? Request your provider →" (GitHub link)
- Selection stored in `AppState.settings.providerId`

**Step 4: Benefit Year Configuration**
- "When does your FSA year run?"
  - Option A: Jan 1 – Dec 31 (most common)
  - Option B: Custom dates (date pickers for start/end)
- "Does your plan have a grace period or rollover?"
  - None / 2.5-month grace period / Rollover (up to $X)
- "How much did you elect this year?" (optional, for dashboard PRD-005)

**Step 5: All Set!**
- Summary of configuration
- "Start Your First Scan" → triggers PRD-001 flow
- "I'll do this later" → goes to main popup home

### FR-3: Progress Persistence
- Onboarding progress saved to storage at each step.
- If user closes the popup mid-onboarding, they resume where they left off.

### FR-4: Re-run Onboarding
- Settings page includes "Reconfigure / Change Provider" button.
- Resets `onboardingComplete = false` and re-launches onboarding.
- Preserves existing scan history and claims.

### FR-5: Contextual Help Tooltips
- Key UI elements in the main workflow get `?` tooltips referencing onboarding concepts.
- Example: "Benefit Year" label has tooltip: "The date range configured in your setup. Change it in Settings."

### FR-6: Empty State Guidance
- If user reaches main popup before completing onboarding (e.g., opened extension from keyboard shortcut), show an empty state card: "Finish setup to start scanning" with a "Complete Setup" button.

## Technical Notes

- Onboarding UI should be optimized for the popup's 400×600px viewport.
- Use `chrome.permissions.request` for optional permissions — must be in response to a user gesture.
- Required host permissions (Amazon, Navia) must be declared in `manifest.json` and can't be requested dynamically.
- Progress bar at top of onboarding showing current step / total steps.
- Animation: simple fade transitions between steps (no heavy libraries).
